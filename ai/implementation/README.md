# Implementation Briefs

These documents turn [project-plan.md](../project-plan.md) into phase-level work packets.

## How to use them

- Use `project-plan.md` for the overall order, dependencies, and product intent.
- Use the detailed phase document for the phase currently being implemented.
- Treat later briefs as starting contracts, not frozen technical instructions. Update them after earlier phases reveal deployment, state, or realtime constraints.
- Complete the success criteria and validation checks before moving to the next phase.
- Do not combine unrelated phase work into one change set unless the phase brief explicitly requires it.

## Handoff rule

At the end of each phase, record what was learned, what changed from the brief, and what the next phase must know. Keep implementation-specific discoveries in the relevant phase document or repository notes rather than silently changing the roadmap.
